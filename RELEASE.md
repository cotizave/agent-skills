## GitHub Copilot and the version tag

[GitHub CLI's `gh skill publish`](https://cli.github.com/manual/gh_skill_publish) validates the skill, adds the `agent-skills` GitHub topic, and creates a version tag plus a GitHub Release with generated notes. `gh skill publish --dry-run` passed on this checkout; it reported non-blocking recommendations to enable secret scanning, push protection, and tag protection. After reviewing the release content, the maintainer can publish with `gh skill publish --tag v0.3.0`. This is an external publication step and has not been run. It does not submit the skill for approval to a separate Copilot marketplace. [`gh skill search`](https://cli.github.com/manual/gh_skill_search) uses GitHub Code Search, so a release does not guarantee immediate search indexing; direct installation from `cotizave/agent-skills` was tested.

Alternatively, a maintainer can use the GitHub Actions **Create version tag** workflow on `master`, enter the version from `plugin.json`, and let it verify successful CI, build/checksum/upload the ZIP, and create `v<version>`. This path does not create a GitHub Release. **Choose one tag-creation path**: running both for `v0.3.0` will conflict. The workflow-created tag uses `GITHUB_TOKEN`, so its tag event does not trigger another workflow; it uploads the package artifact itself. If using `gh skill publish` and wanting the prepared ZIP on the GitHub Release, attach `dist/cotizave-plugin-0.3.0.zip` as a release asset after the release exists.
